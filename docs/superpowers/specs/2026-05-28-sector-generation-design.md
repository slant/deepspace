# Sector Generation Design

**Date:** 2026-05-28  
**Status:** Approved

## Overview

When a player enters a new sector, the sector is procedurally generated by rolling a d12 a fixed number of times (defined per sector in `map.yml`). Each roll activates at most one trigger hex in that sector. Trigger hexes that are not activated remain completely blank. Static hexes (those with a hardcoded `icon:`) always show.

Alpha sector generates automatically when a campaign is first activated.

## Rules (from PDF page 7)

- Roll d12 N times (N = sector roll count: tau=2, zeta=3, delta=4, beta=6, alpha=6).
- Each roll maps to zero or one trigger hex via that hex's `trigger:` range (e.g. `"3-6"` matches rolls 3, 4, 5, 6).
- If the matched hex is already activated, skip the roll — no replacement roll.
- If no hex matches the roll (shouldn't happen with well-formed data), skip.
- Activated trigger hexes render as `circle` (planet) icons.
- Existing campaigns (already past alpha) are left as-is; no backfill.

## Data

**New column:** `activated_hexes json default '[]' not null` on `campaigns`.

Stores an array of `"q,r"` strings — one entry per activated trigger hex across all sectors. Example: `["0,6", "2,6", "3,4"]`.

## Components

### `MapLoader` (additions)

Three new class methods:

- `trigger_hexes_for_sector(sector)` — returns all hexes in that sector that have a `trigger:` field.
- `parse_trigger(str)` — converts a trigger string to an integer array. `"3-6"` → `[3,4,5,6]`, `"10"` → `[10]`, `"10-12"` → `[10,11,12]`.
- `hex_for_roll(sector, roll)` — finds the trigger hex in the sector whose parsed range includes `roll`. Returns `nil` if none match.

### `Campaign` model (additions)

- `generate_sector!(sector)` — rolls d12 `sector_rolls[sector]` times. For each roll, calls `MapLoader.hex_for_roll`. Appends `"q,r"` to `activated_hexes` if the hex exists and isn't already activated. Saves once with `update!`.
- `hex_active?(q, r)` — returns `activated_hexes.include?("#{q},#{r}")`.
- `discover_sector!` — calls `generate_sector!(sector)` before its existing `update!`. The existing `return if sectors.include?(sector)` guard prevents re-generation.
- `ensure_defaults` — adds `self.activated_hexes ||= []`.

`activate!` already calls `discover_sector!("alpha")`, so alpha generates automatically on campaign start with no additional changes to `activate!`.

### `HexMapComponent` (changes)

New private method `icon_for(hex)`:

```
if hex["icon"].present?  → return hex["icon"]   (static hex, always shown)
elsif hex["trigger"].present? && campaign.hex_active?(q, r)  → return "circle"
else  → return nil
```

The `.html.erb` template replaces `hex["icon"].present?` with `icon_for(hex).present?`, passing `icon_for(hex)` as the icon argument to `HexIconComponent`.

Planet sprite lookup (`planet_index_for`) already handles any `"q,r"` via `campaign.planet_sprite_for`, so activated trigger hexes get a campaign-consistent planet sprite automatically.

## Call Flow

```
Player clicks adjacent hex in new sector
  → HexEventsController#show
    → campaign.move_to!
    → campaign.discover_sector!(sector)       ← existing call
        → campaign.generate_sector!(sector)   ← new, runs first
            → roll d12 N times
            → update!(activated_hexes: [...])
        → update!(discovered_sectors: [...])
        → log! "Entered ... sector"
    → EventCatalog.for_hex
  → JSON response to client
Client: Turbo.visit (frame: "campaign_map")
  → HexMapComponent re-renders
  → icon_for(hex) returns "circle" for newly activated hexes
  → New planets visible
```

## Testing

**`MapLoader`:**
- `parse_trigger` handles single value, range, and multi-digit range.
- `hex_for_roll` returns the correct hex for various rolls in a known sector.
- `hex_for_roll` returns `nil` for a roll that matches no trigger in the sector.

**`Campaign`:**
- `generate_sector!("alpha")` populates `activated_hexes` with coordinates that are all trigger hexes in alpha.
- No duplicate coordinates in `activated_hexes` after generation.
- `hex_active?` returns `true` for an activated hex, `false` for a non-activated trigger hex.
- `discover_sector!` results in `activated_hexes` being populated for the given sector.
- Calling `discover_sector!` twice for the same sector does not re-roll (idempotent).

## Out of Scope

- Backfilling existing campaigns.
- Beacon/store trigger hexes (all trigger hexes in current data become `circle`).
- Re-generation or "reroll" UI.
